# removing a row here moves GNOT between this file and
# INVESTORS_UNLOCKED_ADDRESS rather than changing total supply.
#
# WHY A PARTICIPANT MAY BE MISSING
#
# Participants name the gno.land address they want their GNOT at by signing a
# message with the Ethereum wallet that paid, at
# https://sale.gno.land/distribution. That page has no deadline and the list
# keeps growing. Genesis has to be cut at some instant; whoever had not bound by
# then is owed their allocation out of the multisig row, distributed by hand.
# Anyone binding after the snapshot falls in the multisig share. If genesis
# slips, re-extract and rebuild.
#
# 26 OF THE 78 ALSO HOLD AN AIRDROP ENTITLEMENT
#
# They appear both here and in allocate/genbalance.txt.gz, for 675,669.367465
# GNOT of airdrop between them. This is expected — the sale audience overlaps
# the Cosmos Hub / AtomOne one, and a gno address is the same 20-byte key as the
# cosmos address it was derived from. mkgenesis/build.go's accumulate() SUMS
# them, which is the intended treatment: the airdrop is for holding ATOM/ATONE
# at the 2022/2024 snapshots, the sale entitlement is for paying USD in 2026,
# and neither is conditioned on the other. TestPublicSaleOverlapIsSummed pins
# the set so that it cannot change without someone noticing.
#
# NO LOCKUP, WITH ONE EXCEPTION
#
# Sale allocations are lockup-free and fully liquid at genesis, so they carry no
# §132 schedule. mkgenesis knows a row came from this file and subtracts it from
# the amount the common schedule is computed over — which is what makes the 26
# overlapping rows come out right: their AIRDROP portion still vests, their sale
# portion does not.
#
# The one exception is `lockup_12m = yes` in the settlement: a US accredited
# investor whose bid Sonar signed with `forcedLockup`. That row declares its own
# schedule below — a 12-month cliff to 2027-09-10T00:00:00Z, over the sale
# portion only, since the restriction attaches to what was purchased and not to
# that address's airdrop.
#
# That address is one of the 26, and one address carries at most one schedule —
# so the declared cliff REPLACES the common §132 schedule rather than stacking
# with it, and its 1,995.215082 GNOT of airdrop ends up unscheduled. The
# alternative is to express nothing at all, which is worse.
#
# THAT ONE SCHEDULE IS ONLY EMITTED WHEN VESTING IS ON. Like every other
# schedule in this pipeline it is opt-in (`make VESTING_START=… VESTING_END=…`),
# and the committed balances.txt.gz is built with vesting OFF. `mkgenesis build`
# prints a loud warning when it drops a declared schedule, because with the
# schedule dropped the restriction has to be honoured by hand instead.
#
